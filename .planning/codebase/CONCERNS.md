# Codebase Concerns

## Tech Debt

### All Three Projects Are Scaffold State — Zero Business Logic

- **Issue:** Every sub-project (`be-cadelfriul`, `bo-cadelfriul`, `fe-cadelfriul`) is in its raw scaffolding state. There are no services, repositories, controllers, components, pages, API calls, or any domain logic implemented anywhere.
- **Files:**
  - `be-cadelfriul/src/main/java/com/cadelfriul/backend/` — Only Application entry point, two config classes, and 3 entity POJOs.
  - `bo-cadelfriul/src/app/` — Empty routes, default Angular starter template.
  - `fe-cadelfriul/src/app/` — Default Next.js starter page with "Create Next App" content.
- **Impact:** The project is not yet functional. Any planning or estimation based on these files is speculative.
- **Fix approach:** Implement the layers defined in `OpenApiConfig.java` (Hospitality, Wellness, E-Commerce, E-Bike modules) with controllers, services, repositories, and DTOs. Wire up the Angular and Next.js frontends with actual routes and views.

### Placeholder Templates Still in Place

- **Issue:** Both frontend boilerplate pages still contain auto-generated starter content.
  - `fe-cadelfriul/src/app/page.tsx` shows "To get started, edit the page.tsx file." and links to Vercel/Next.js docs.
  - `bo-cadelfriul/src/app/app.html` contains the full Angular logo SVG and "Hello, {{ title() }}" — this is the generator boilerplate.
- **Files:**
  - `fe-cadelfriul/src/app/page.tsx` — All 65 lines are placeholder.
  - `bo-cadelfriul/src/app/app.html` — All 344 lines are placeholder (template + inline styles + SVG).
- **Impact:** The application has no branded content. Ship-blocking for any user-facing launch.
- **Fix approach:** Replace with project-specific landing content, remove inline template styles, extract to proper stylesheets.

### Empty Routes Configuration

- **Issue:** `bo-cadelfriul/src/app/app.routes.ts` exports an empty `Routes` array. No Angular routing is configured despite the app scaffolding including `<router-outlet />` in the template.

### FE Metadata Still Default

### Auto-Generated HELP.md Committed

- **Files:**
  - `be-cadelfriul/HELP.md` — 28 lines of generic Spring Boot links.

### Admin Password Stored as Plaintext

- **Issue:** `Admin.java` stores the password field as a plain `String` with no reference to password encoding (no `@JsonIgnore` on getter, no `@PrePersist`/`@PreUpdate` hook, no `BCryptPasswordEncoder` usage). The `getPassword()` method exposes the raw password via serialization.
- **Files:**
  - `be-cadelfriul/src/main/java/com/cadelfriul/backend/core/auth/entity/Admin.java` — Lines 20, 50.
- **Impact:** Critical vulnerability. If this entity is serialized to JSON (e.g., in an API response), plaintext passwords are exposed. If passwords are stored without hashing, a database breach leaks all credentials.
- **Fix approach:** Add a Spring Security `PasswordEncoder` bean, hash passwords on write, never expose the password field in JSON responses (use `@JsonIgnore` on getter and/or a DTO projection).

## Security Considerations

### Hardcoded Database Credentials in application.properties

- **Risk:** `application.properties` contains production-level database connection details with hardcoded username (`postgres`) and password (`postgres`) committed to the repository.
- **Files:**
  - `be-cadelfriul/src/main/resources/application.properties` — Lines 4-6.
- **Current mitigation:** None. The values are committed in plaintext.
- **Recommendations:**
  1. Remove credentials from committed file.
  2. Use environment variables: `spring.datasource.username=${DB_USERNAME}` and `spring.datasource.password=${DB_PASSWORD}`.
  3. Create an `application-prod.properties` (gitignored) or use Spring Boot's external configuration.
  4. Rotate the exposed credentials if they've been used on any real system.

### Security Config Disables All Protections

- **Risk:** `SecurityConfig.java` disables CSRF protection and permits all requests (`anyRequest().permitAll()`). The comments acknowledge "solo per lo sviluppo" (only for development), but there is no profile guard or alternative config for production.
- **Files:**
  - `be-cadelfriul/src/main/java/com/cadelfriul/backend/core/config/SecurityConfig.java` — Lines 14-17.
- **Current mitigation:** None — no `@Profile("dev")` annotation, no production security configuration exists.
- **Recommendations:**
  1. Activate this permissive config only under `@Profile("dev")`.
  2. Create `SecurityConfigProd.java` with proper CSRF protection, CORS policy, and authenticated endpoints.
  3. Add role-based access using `AdminRole` (SUPER_ADMIN, RECEPTIONIST) enforcement.

### No HTTPS / TLS Configuration

- **Risk:** No SSL/TLS configuration is present. The server runs on plain HTTP port 8080.
- **Files:**
  - `be-cadelfriul/src/main/resources/application.properties` — Line 16: `server.port=8080`.
- **Current mitigation:** None.
- **Recommendations:** Configure `server.ssl.key-store*` properties or terminate TLS at a reverse proxy (NGINX, load balancer). Add `@Configuration` binding for production SSL.

### No Input Validation on Entities

- **Risk:** Entity fields have `@Column(nullable = false)` constraints but no validation annotations (`@NotBlank`, `@Email`, `@Size`, etc.). Malformed or malicious data can be persisted.
- **Files:**
  - `be-cadelfriul/src/main/java/com/cadelfriul/backend/core/auth/entity/Admin.java` — Email field lacks `@Email` / `@Pattern` validation.
  - `be-cadelfriul/src/main/java/com/cadelfriul/backend/core/auth/entity/AdminLog.java` — Action and details fields have no size constraints beyond the column definition.
- **Recommendations:** Add `jakarta.validation` annotations and a `@Valid` controller parameter or `@ControllerAdvice` for validation error handling.

### No .env.example Files

- **Risk:** The root `.gitignore` ignores `.env` and `.env*.local` files, but there is no `.env.example` to document required environment variables. New developers have no reference for what to configure.
- **Files:**
  - Root `.gitignore` — Line 21-22: `.env*.local` and `.env` are ignored.
- **Recommendations:** Create `.env.example` files at the repo root and/or in each sub-project documenting all required environment variables (DB URL, credentials, JWT secret, API base URLs, etc.).

## Performance Bottlenecks

### No Connection Pool Configuration

- **Problem:** The datasource uses default HikariCP settings. No pool size, timeout, or leak-detection parameters are configured.
- **Files:**
  - `be-cadelfriul/src/main/resources/application.properties` — Lines 4-6.
- **Cause:** Default settings may be insufficient under load.
- **Improvement path:** Add `spring.datasource.hikari.*` properties for maximum pool size, connection timeout, idle timeout, and leak detection threshold.

### Hibernate SQL Logging Enabled by Default

- **Problem:** `spring.jpa.show-sql=true` and `hibernate.format_sql=true` are enabled, which causes console logging of every SQL statement. In production this adds I/O overhead and may leak schema details.
- **Files:**
  - `be-cadelfriul/src/main/resources/application.properties` — Lines 11-12.
- **Improvement path:** Move these settings to `application-dev.properties` or `application-local.properties`, disabled in production profile.

### No Client-Side Caching Strategy

- **Problem:** Neither frontend has any caching, SWR, React Query, or Angular caching/interceptor setup. Every navigation or re-render will re-fetch all data.
- **Files:**
  - `fe-cadelfriul/` — No HTTP client or caching library in `package.json`.
  - `bo-cadelfriul/` — No HTTP interceptor or caching setup in `app.config.ts`.
- **Improvement path:** Add TanStack Query (React) or Angular HTTP interceptors with caching headers. Set up proper `Cache-Control` on backend responses.

## Fragile Areas

### Extremely Aggressive Version Adoption

- **Why fragile:** Every major technology in the stack is on its very latest (and in some cases first-stable) version, increasing the risk of undocumented breaking changes or ecosystem immaturity:
  - Spring Boot `4.1.0` — Released as milestone/RC, limited community support.
  - Java `26` — Cutting-edge JDK, not all libraries are compatible.
  - Gradle `9.6.0` — Very latest, may have plugin compatibility issues.
  - Angular `21.2.x` — Latest major, Angular's rapid release cycle means frequent breaking changes.
  - Next.js `16.2.10` — Latest, with breaking changes as noted in `AGENTS.md`.
  - React `19.2.4` — Latest major with compiler mode enabled.
- **Files:**
  - `be-cadelfriul/build.gradle.kts` — Spring Boot 4.1.0, Java 26.
  - `fe-cadelfriul/package.json` — Next.js 16.2.10, React 19.2.4.
  - `bo-cadelfriul/package.json` — Angular 21.2.x.
- **Safe modification:** Pin exact versions in `package.json` (remove `^` prefix). Run full test suite before upgrading any dependency. Document known-breaking changes in a `BREAKING.md`.
- **Test coverage:** No regression tests exist to catch regressions from version updates.

### No Error Boundaries or Global Error Handling

- **Why fragile:** Both frontends lack error boundaries, error states in components, or global error handlers.
  - `fe-cadelfriul/src/app/layout.tsx` — No React error boundary wrapping the app.
  - `bo-cadelfriul/src/main.ts` — Only a generic `.catch((err) => console.error(err))`.
- **Safe modification:** Wrap the React app in an error boundary component. Add Angular `ErrorHandler` class for centralized error reporting.
- **Test coverage:** Not tested.

### Spring Boot Test Is a No-Op

- **Why fragile:** The only backend test (`BeCadelfriulApplicationTests.java`) is the default context-loads test. It only verifies the application context starts. If any bean fails to wire, this test catches it, but there are zero unit tests for entities, zero integration tests, zero security tests.
- **Files:**
  - `be-cadelfriul/src/test/java/com/cadelfriul/backend/BeCadelfriulApplicationTests.java` — 13 lines, 1 no-op test.
- **Safe modification:** Write tests alongside new code. Do not rely on the context-loads test for coverage.
- **Test coverage:** 0% line coverage.

### Angular Spec Test Will Likely Fail

- **Why fragile:** The test in `app.spec.ts` asserts `compiled.querySelector('h1')?.textContent` contains `"Hello, bo-cadelfriul"`, but the template renders `Hello, {{ title() }}` as an Angular signal expression. Once the template is replaced with real content, this test will fail. It also imports `App` directly without `HttpClientTestingModule` or `RouterTestingModule` which would be needed for real components.
- **Files:**
  - `bo-cadelfriul/src/app/app.spec.ts` — Lines 17-21.
- **Safe modification:** Update or remove this placeholder test as soon as real content is added.
- **Test coverage:** Single smoke test, not meaningful.

- **Issue:** The root `.gitignore` does not cover `**/.gradle/` or `**/build/`. The `be-cadelfriul/.gitignore` covers them locally, but if someone adds a sub-project at the root level or moves files, these could leak. The `.gradle/` and `build/` directories currently exist in the working tree.
- **Files:**
  - Root `.gitignore` — Missing `**/.gradle/`, `**/build/`, `**/bin/`.
  - `be-cadelfriul/.gitignore` — Has `.gradle` and `build/` (good for that sub-project).

### .env* Safety Only Partial

- **Issue:** Root `.gitignore` covers `.env*.local` and `.env`, but `.env.production`, `.env.staging`, or similar files (without `.local` suffix) could be committed. There is also no explicit ignore for files like `.env.dev`, `.env.test`.
- **Files:**
  - Root `.gitignore` — Lines 21-22.

## Configuration Drift

### No Spring Profiles

- **Issue:** Only one `application.properties` file exists. No `application-dev.properties`, `application-prod.properties`, or `application-test.properties`. Environment-specific overrides cannot be managed cleanly.
- **Files:**
  - `be-cadelfriul/src/main/resources/application.properties` — Single file.
- **Impact:** All environment tuning (DB credentials, logging, pool settings) must be done via external env vars or by modifying the committed file.
- **Fix approach:** Use `@Profile` annotations on config beans and create profile-specific property files.

### Tailwind Version Mismatch Between Frontends

- **Issue:** `bo-cadelfriul` uses `@tailwindcss/postcss: ^4.1.12` while `fe-cadelfriul` uses `@tailwindcss/postcss: ^4`. These could resolve to different minor/patch versions, causing styling inconsistencies.
- **Files:**
  - `bo-cadelfriul/package.json` — Line 31: `"@tailwindcss/postcss": "^4.1.12"`.
  - `fe-cadelfriul/package.json` — Line 17: `"@tailwindcss/postcss": "^4"`.
- **Impact:** Design system drift between the two frontend applications.
- **Fix approach:** Align both versions to the same semver range.

### vitest as devDependency but ng test Used

- **Issue:** `bo-cadelfriul/package.json` includes `vitest: ^4.0.8` as a devDependency and `tsconfig.spec.json` references `vitest/globals`, but the test script runs `ng test` (Angular CLI's built-in test runner, which uses Karma/Jasmine by default). This is a mismatch — vitest is unused unless explicitly configured.
- **Files:**
  - `bo-cadelfriul/package.json` — Line 39: `"vitest": "^4.0.8"`.
  - `bo-cadelfriul/package.json` — Line 9: `"test": "ng test"`.
  - `bo-cadelfriul/tsconfig.spec.json` — Line 8: `"types": ["vitest/globals"]`.
- **Impact:** Confusion about the test framework. The spec configuration references vitest types but tests use `@angular/core/testing` and `describe/it/expect` from Jasmine.
- **Fix approach:** Either fully configure vitest with `@analogjs/vitest-angular` or remove the vitest dependency and use the Angular CLI's native test builder consistently.
