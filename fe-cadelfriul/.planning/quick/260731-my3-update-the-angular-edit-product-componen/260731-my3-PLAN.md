<objective>
Update the Angular "Edit Product" dialog in the `bo-cadelfriul` sibling project to render visual previews of the product's **existing** images (from the backend `imageUrls` array) as premium thumbnails with a mock delete ("X") button.

Purpose: The dialog currently previews existing images using the stale `product.imageIds` → `/api/products/images/{id}` convention, while the backend already returns a ready-to-prefix `imageUrls` array (the products grid and the Room dialog both use this convention — `room-edit-dialog` implements exactly the requested pattern). This task aligns the Product dialog with the current backend contract and the app's own image-preview convention, and gives admins the ability to visually remove thumbnails before saving.

Output: `imageUrls` added to the `Product` TS interface; the dialog's class logic replaced with an `existingImageUrls` array + mock `removeExistingImage(index)`; the inline template upgraded with a `gap-3` flex thumbnail grid (premium classes, absolute "X" per image) above the file input.

**Implementation notes (locked decisions):**
- **The component is standalone with an INLINE template** — there are no `.html`/`.scss` files for this dialog. All template edits go inside the `template:` string in `product-edit-dialog.component.ts`. Do not create separate template/style files.
- **`product.imageUrls` requires a model fix first** — the `Product` interface currently declares only `imageIds: string[]`, but the backend returns `imageUrls` (the products grid column reads `field: 'imageUrls'` and `data-grid.getImageUrl()` resolves them). Adding `imageUrls: string[]` to the interface is mandatory or the new mapping will not compile. Leave `imageIds` untouched (removing it is out of scope and the backend may still return it).
- **URL mapping follows the `room-edit-dialog` convention** (the user's `environment.apiUrl + url` example, hardened): `url.startsWith('http') ? url : \`${environment.apiUrl}${url}\`` — passthrough for already-absolute URLs, prefix otherwise. Do NOT use the old `imageIds` → `/api/products/images/{id}` mapping anymore.
- **Delete action is MOCK ONLY** — `removeExistingImage(index)` splices from `existingImageUrls` for visual feedback. Per locked decision: no backend delete call, NO `removedImageUrls` tracking array (the room dialog tracks removals; this task explicitly does not).
- **New-file previews are untouched** — `imagePreviewUrls` + `onFilesSelected` keep their current behavior; after this change they hold only newly selected files (existing images move to `existingImageUrls`).
- Zero new npm dependencies.
