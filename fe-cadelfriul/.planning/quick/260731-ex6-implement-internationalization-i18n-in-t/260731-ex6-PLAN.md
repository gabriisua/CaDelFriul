## CRITICAL — Next.js 16 breaking changes (verified in node_modules/next/dist/docs)

1. **`middleware.ts` is DEPRECATED and renamed to `proxy.ts`** (Next.js 16.0.0). The file convention is `src/proxy.ts` exporting a named `proxy` function + `config.matcher`. The project ALREADY has `src/proxy.ts` (auth route protection) — extend it, do NOT create `middleware.ts`. next-intl v4's official docs use `proxy.ts` with `createMiddleware` from `next-intl/middleware` for Next.js 16.
2. **Async `params`**: `params` is a `Promise` — layouts/pages must `await params` (e.g. `const { locale } = await params`).
3. Route groups stay as groups INSIDE the `[locale]` segment: `src/app/[locale]/(vetrina)`, `[locale]/(auth)`, `[locale]/dashboard` — preserving existing nested layouts (vetrina Header/Footer layout, auth clean layout, dashboard sidebar layout) without edits.

## next-intl v4 App Router setup (verified against next-intl.dev/docs, v4)

- `src/i18n/routing.ts` — `defineRouting({ locales, defaultLocale })` from `next-intl/routing`
- `src/proxy.ts` — `createMiddleware(routing)` from `next-intl/middleware`; always returns a `NextResponse` (pass-through = status 200, locale negotiation = 307/308 redirect)
- `src/i18n/navigation.ts` — `createNavigation(routing)` from `next-intl/navigation` → `{ Link, redirect, usePathname, useRouter, getPathname }`. `usePathname()` returns the pathname WITHOUT the locale prefix; `useRouter`/`Link` auto-prefix the active locale
- `src/i18n/request.ts` — `getRequestConfig` from `next-intl/server` + `hasLocale` from `next-intl`
- `[locale]/layout.tsx` — `hasLocale(routing.locales, locale)` guard → `notFound()`, then `setRequestLocale(locale)` (from `next-intl/server`) BEFORE `getMessages()`, `NextIntlClientProvider` with explicit `messages`, `generateStaticParams()` returning `routing.locales.map((locale) => ({ locale }))` for static rendering of all 3 locales
