<objective>
Refactor the PDP at `src/app/[locale]/(vetrina)/shop/[id]/page.tsx` to fetch real product data from the Spring Boot API (`GET /api/products/{id}`) instead of the module-level mock, and map every UI section to the live data.

Purpose: The PDP was created in quick task 260731-lfb with mock data. The Shop listing (`/shop`) already fetches from the API via `fetchProducts()` — the detail page must match, so guests see real product info, real images, and add the actual product to their cart. This closes the gap between the listing and detail views.

Output: Extended API client (`fetchProduct` + `attributes` on the Product interface) and a refactored PDP with loading/error states, `getImageUrl`-prefixed image arrays, dynamic attribute accordions, and real-id add-to-cart. One focused test file mirrors the existing `success/page.test.tsx` conventions.

**Implementation notes (locked decisions):**
- **Use the existing API client, not raw `fetch`** — per planning constraints. `fetchProduct(id)` goes through `apiFetch` (base URL, auth headers, 401/403 handling), and `getImageUrl()` is the codebase's existing partial-path→full-URL helper (used by ProductCard/RoomCard; it also passes through already-absolute `http(s)` URLs, more robust than blind prefixing).
- **Mock `features` bullet list is removed** — the API has no `features` field. Its job is taken over by the dynamic accordions from `attributes`.
- **Accordion section hidden when `attributes` is empty** — the task explicitly sanctions "hide those sections" as the fallback; no hardcoded placeholder text for a product that isn't the lavender oil.
- **Keep `use(params)`** for the Next 16 promise `params` (already correct per `node_modules/next/dist/docs/.../page.md` — Client Components read the promise via React's `use`).
- **Stock guards mirror `/shop` page** (`stockQuantity` may be undefined; `available` drives the "Unavailable" button state).
