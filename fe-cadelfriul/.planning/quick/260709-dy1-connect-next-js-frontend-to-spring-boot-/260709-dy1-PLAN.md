<task type="auto">
  <name>Task 1: Create typed API client at src/lib/api.ts</name>
  <files>src/lib/api.ts</files>
  <action>
    Create `src/lib/api.ts` with the following:

    1. **Config**: Read `NEXT_PUBLIC_API_URL` from `process.env` — fall back to `http://localhost:8080` if not set. Use `NEXT_PUBLIC_` prefix because this code runs in the browser.

    2. **`UserProfile` type**: `{ id: string; name: string; email: string; phone?: string }`

    3. **`AuthError` class**: Extends `Error`, includes `status: number` and optional `body: unknown`. Used for consistent error handling.

    4. **`apiFetch<T>(path, options?)` — private fetch wrapper**:
       - Prepends `API_BASE_URL` to `path`
       - Default headers: `Content-Type: application/json`
       - Sets `credentials: 'include'` — critical: this sends HttpOnly cookies (set by Spring Boot on login) with every request for JWT Bearer auth
       - On non-ok response: reads body as JSON, throws `AuthError` with status and parsed body
       - On ok: returns parsed JSON as `T`

    5. **`login(email, password)`**:
       - POST to `/api/auth/login` with JSON body `{ email, password }`
       - Returns `Promise<UserProfile>`
       - The Spring Boot API sets an HttpOnly cookie on success — no token handling needed in JS

    6. **`fetchProfile()`**:
       - GET `/api/profile`
       - Returns `Promise<UserProfile>`
       - 401 means not authenticated — let the caller handle redirect

    7. **`logout()`**:
       - POST `/api/auth/logout`
       - Returns `Promise<void>`
       - Spring Boot clears the session cookie

    8. **DO NOT** store tokens in localStorage, sessionStorage, or any JS variable — the JWT travels in an HttpOnly cookie set by Spring Boot. Per the ROADMAP: "User session persists via HttpOnly cookie (no localStorage tokens)."

    9. **Export all public functions and types**: `login`, `fetchProfile`, `logout`, `AuthError`, `UserProfile`.
  </action>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-DY1-01 | Spoofing | Login form | mitigate | Email/password validated on client (required fields, email type) before API call |
| T-DY1-02 | Tampering | API client fetch | mitigate | All requests use `credentials: 'include'` — JWT is in HttpOnly cookie, never accessible to JS |
| T-DY1-03 | Info Disclosure | Error messages | mitigate | Generic error messages shown to user ("Invalid email or password"), never raw API error bodies |
| T-DY1-04 | Repudiation | Logout | accept | Best-effort logout; if API unreachable, still redirect user |
