# Quick Task 260716-g37: Implement GET /api/admin/orders/{id} endpoint

## Objective

Add GET /api/admin/orders/{id} endpoint for retrieving a single order by ID with full details.

## Changes Made

### Task 1: Add getOrderById to OrderService

**File:** `src/main/java/com/cadelfriul/backend/ecommerce/service/OrderService.java`

Added `getOrderById(UUID orderId)` method:
- Annotated with `@Transactional(readOnly = true)` for read optimization
- Uses `orderRepository.findById(orderId).orElseThrow()` with RuntimeException for 404 behavior
- Reuses existing `toResponse(Order)` helper to avoid duplication
- Placed after `getAllOrders()` and before `updateOrderStatus()` for logical grouping

### Task 2: Add GET /{id} endpoint to AdminOrderController

**File:** `src/main/java/com/cadelfriul/backend/ecommerce/controller/AdminOrderController.java`

Added `getOrderById` endpoint:
- `@GetMapping("/{id}")` maps to GET /api/admin/orders/{id}
- `@Operation(summary = "Get order by ID", description = "Get detailed information about a specific order")` for Swagger
- Method signature: `public ResponseEntity<OrderResponse> getOrderById(@PathVariable UUID id)`
- Returns `ResponseEntity.ok(orderService.getOrderById(id))`
- Inherits `@PreAuthorize("hasRole('SUPER_ADMIN'))` from class-level annotation
- Placed between `getAllOrders()` and `updateOrderStatus()` for logical ordering

## Verification

- Compilation: `gradle compileJava` — BUILD SUCCESSFUL
- Both methods exist and are properly annotated
- Endpoint returns OrderResponse for existing orders
- Endpoint throws RuntimeException (resulting in 500/404 behavior) for non-existent orders
